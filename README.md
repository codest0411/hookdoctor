# hookdoctor

Offline, read-only Git hook diagnostics: find out why your Git hooks silently don't run.

## The Problem

Git hooks fail silently by design:
- *"My lint hook never runs on my laptop, even though it's in `.husky/pre-commit`."* (`core.hooksPath` was never set because `npm install` ran with `--ignore-scripts` or `HUSKY=0`.)
- *"I have hooks in `.git/hooks/pre-commit`, why does Git ignore them?"* (A global `core.hooksPath` overrides `.git/hooks`, or the file lacks `+x` on macOS/Linux, or `advice.ignoredHook` is `false`.)
- *"My hook fails with `No such file or directory`."* (Line 1 has CRLF `\r\n` endings or `#!/usr/bin/env node` isn't on `PATH`.)
- *"My hook worked last month, now it fails."* (`npm run lint-staged` was renamed in `package.json`.)

`hookdoctor` inspects your repository offline and read-only (never executing any hook or script) and explains the exact decision chain.

## Quick Start

```bash
npx hookdoctor
```

Explain why a specific hook will or will not run:

```bash
npx hookdoctor why pre-commit
```

Add an optional script to your project's `package.json`:

```json
{
  "scripts": {
    "hooks:check": "hookdoctor"
  }
}
```

## Diagnostic Rules

| Rule | Severity | What it catches |
| --- | --- | --- |
| `HD001` | `error` | Hook manager (`husky`, `lefthook`, `simple-git-hooks`, `pre-commit`) declared or expected, but not installed |
| `HD002` | `error` | `core.hooksPath` points to a missing or non-directory path |
| `HD003` | `warn` | Global/system `core.hooksPath` overrides repo hooks, or orphaned hooks exist in `.git/hooks` |
| `HD004` | `error` | Direct hook file lacks `+x` executable bit (POSIX; skipped on Windows / `core.fileMode=false`) |
| `HD005` | `error`/`warn` | Missing shebang, CRLF on line 1, or missing interpreter on `PATH` |
| `HD006` | `warn`/`info` | Install step skipped (`prepare`/`postinstall` missing, `ignore-scripts=true` in `.npmrc`, `HUSKY=0`, `CI`) |
| `HD007` | `warn` | Multiple hook managers declared or conflicting `core.hooksPath` entries |
| `HD008` | `warn` | Hook or manager config references a missing `package.json` script |
| `HD009` | `info` | Inventory table of every standard Git hook present (`active`, `inactive`, `ignored`) |

See [docs/RULES.md](docs/RULES.md) for detailed examples.

## CLI Options

```text
hookdoctor [path] [options]
hookdoctor why <hook-name> [path] [options]
```

- `--format <human|json|github|sarif>`: Output format (default: `human`)
- `--fail-on <error|warn|never>`: Exit `1` threshold (default: `error`)
- `--ci`: Treat `CI` environment detection as informational (`HD006`)
- `--no-color`: Disable ANSI colors
- `--config <path>`: Path to `.hookdoctorrc.json`

Exit codes: `0` healthy, `1` findings at/above `--fail-on`, `2` runtime/usage error (not a Git repo, Git missing/too old, dubious ownership).

## Configuration (`.hookdoctorrc.json`)

```json
{
  "expectedManagers": ["husky"],
  "failOn": "error",
  "ignore": [
    {
      "rule": "HD006",
      "reason": "Hooks are intentionally skipped on CI runners"
    }
  ]
}
```

## FAQ

**How is this different from each manager's own troubleshooting docs?**
Manager tools only check themselves and often assume you already know which manager is supposed to be active. `hookdoctor` starts from Git's own resolution (`git config --show-scope --show-origin` and `git rev-parse --git-path hooks`), detects conflicts between managers, checks `.npmrc`/`HUSKY=0`/shebangs/missing npm scripts, and explains the full chain in one command.

## Honest Limitations

- **Line-based parsing:** `lefthook.yml` and `.pre-commit-config.yaml` are parsed line-by-line (zero runtime dependencies); advanced YAML features like anchors or remote includes are not expanded.
- **Recognized managers:** Manager-specific install checks cover `husky`, `lefthook`, `simple-git-hooks`, and `pre-commit`. Unknown custom hook installers are still checked for directory existence, `+x`, shebangs, and npm scripts.
- **Does not run hooks:** `hookdoctor` is strictly read-only and offline, so it cannot prove that a hook's linter or test suite will pass when executed.

See [docs/LIMITATIONS.md](docs/LIMITATIONS.md) for details.
